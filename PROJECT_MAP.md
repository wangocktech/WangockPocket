## 1. Что это за приложение

Одностраничное портфолио разработчика Wangock, оформленное как портативная игровая консоль. Внутри — «Обо мне», проекты, прайс и контакты. На странице нет отдельных шапки, подвала и обычной навигационной панели.

Технологии самого сайта: HTML, CSS, JavaScript ES modules, нативные SVG и HTMLAudioElement. React, Next.js, Vue, Supabase и другие технологии в карточках — содержимое демонстрационных проектов, а не зависимости приложения.

Нет сборки, npm-зависимостей, backend API, базы данных, авторизации, аналитики, service worker и серверного рендеринга. Node.js нужен для локальной раздачи файлов и проверок; на production статические файлы обслуживает Nginx.

Ключевое продуктовое правило: **LCD только показывает информацию**. Выбор и действия выполняются кнопками корпуса либо клавиатурой. Пункты на экране — `div`, касания и колесо мыши не управляют экраном. Это намеренное поведение, закреплённое CSS и браузерными тестами.

## 3. Поток выполнения

```text
index.html → app.js
               ├── content.js → portfolio
               ├── navigation.js → initialState(), navigate()
               └── sound.js → ButtonSounds → assets/sounds/*.wav

click / keydown
  → control() / togglePower() / toggleSound()
  → transition(action)
  → navigate(state, action)
  → render()
  → новый DOM экрана + CSS/ARIA-состояние + announcer
```

При импорте `app.js` получает постоянные DOM-узлы, создаёт начальное состояние, читает настройку звука, создаёт `ButtonSounds`, устанавливает обработчики и рисует выключенный экран. Включённый ранее звук не вызывает autoplay.

`render()` каждый раз полностью заменяет `#screen-content.innerHTML`. В обработчиках динамических экранных узлов потребности сейчас нет. События назначены постоянным кнопкам корпуса и документу.

`transition()` сравнивает состояние по ссылке и пропускает рендер при no-op. При изменении сбрасывает toast, перерисовывает экран и объявляет маршрут либо выбор. `scrollIntoView()` вызывается только для действий `move` и `select`.

## 4. Состояние и маршруты

```js
{
  power: 'off',                 // off | boot | on
  route: { name: 'menu', selected: 0, page: 0 },
  history: []                  // предыдущие route
}
```

`power`: из off создаёт чистое boot, из boot/on возвращает чистое off. `ready` переводит только boot в on. Все остальные действия игнорируются, пока питание не on.

`open` сохраняет копию route в history и создаёт новый route с defaults selected/page=0. `back` восстанавливает вершину стека целиком. `menu` возвращает первый menu из истории и очищает стек; без такого элемента создаёт меню с выбором 0. Поэтому SELECT уже в главном меню возвращает выбор на первый пункт.

`move` циклически меняет selected или явно указанное поле page; интерфейс передаёт delta ±1. `select` напрямую устанавливает индекс: сейчас используется тестами, а не пользовательским вводом. Reducer не валидирует схему маршрутов, индексы и содержимое.

```text
menu
├─ about (page)
├─ projects (selected)
│  └─ project (index)
│     ├─ внешняя ссылка demoUrl, если допустима
│     ├─ project-preview, если demoUrl отсутствует/недопустима
│     │  └─ contacts
│     └─ внешняя ссылка sourceUrl, если допустима
├─ pricing (selected)
│  └─ service (index)
│     └─ contacts
├─ contacts
│  ├─ внешняя ссылка Telegram
│  └─ копирование handle
└─ arcade (selected)
   ├─ snake (отдельная игровая сессия)
   └─ tetris (отдельная игровая сессия)
```

Внешняя ссылка и копирование — действия, не маршруты. Возврат из contacts, открытых из услуги или обзора, ведёт к соответствующему родителю. `project.id` не участвует в маршрутизации: `route.index` — позиция в массиве. URL страницы и browser history не отражают выбранный экран; прямых ссылок на разделы нет.

Питание, история и выбор находятся только в памяти. Единственная сохраняемая настройка — `localStorage['wangock-sound']`, строка `on` или `off`. Ошибки доступа к хранилищу перехватываются.

## 5. Управление и таймеры

| Действие | Кнопка | Клавиатура |
| --- | --- | --- |
| Включение | START или питание | Enter, Space, P |
| Выбор/перелистывание | Четыре направления | Стрелки |
| Подтверждение | A или START | A, Enter, Space |
| Возврат | B | B, Escape, Backspace |
| Главное меню | SELECT | Tab до SELECT, затем Enter/Space |
| Переключение питания | OFF/ON | P |
| Звук | SOUND | M |
| Начать / продолжить игру | A или START | A / Enter / пробел |
| Змейка | Крестовина; B — пауза | Стрелки; B / Esc — пауза |
| Тетрис | ←/→ — двигать, ↓ — падение, ↑/A — поворот, B — пауза | Стрелки, A / Enter, B / Esc |

`event.code` привязывает A/B/M/P к физическим клавишам независимо от раскладки. Alt/Ctrl/Meta, композиционный ввод и события внутри полей редактирования пропускаются. Повторы стрелок разрешены; повторы подтверждения, возврата, M и P подавляются.

`tabNavigation` отличает явный обход кнопок через Tab от управления консолью. После Tab Enter/Space активируют сфокусированную кнопку штатно. После pointerdown или стрелок Enter снова подтверждает экранный выбор, даже если фокус остался на ранее нажатой кнопке B или SOUND.

В «Обо мне» все направления и A/START перелистывают страницы. В остальных разделах при нескольких `[data-index]` стрелки меняют выбор, при 0/1 пункте — прокручивают `.screen-main` на 75 px. Left/up дают −1, right/down дают +1.

Переход boot → on происходит через 950 мс, при reduced motion — через 80 мс. Выключение отменяет предыдущий boot timer. Визуальное нажатие длится 110 мс, toast — 2500 мс. Необязательный параметр destination у `togglePower()` сейчас нигде не передаётся.

## 6. Контент и безопасность рендера

Сейчас определены 2 страницы about, 3 демопроекта ORBIT/FORMA/PIXEL SHOP и 3 услуги. Все проекты имеют `isDemo: true`, `demoUrl: null`, `sourceUrl: null`; цены обозначены как примеры.

Проект содержит name/type/category/year/description, массивы stack/features, art и URL. Услуга — name/price/timing/description и массив includes. About — title/text/note/tags. `projects: []` имеет отдельный экран-заглушку; аналогичной обработки пустого about нет.

`escapeHTML()` экранирует текстовые данные перед вставкой в HTML. `safeUrl()` принимает только абсолютные HTTP(S) URL; относительные адреса и другие протоколы отбрасываются. Ссылки дополнительно проверяются при активации и открываются с `noopener,noreferrer`.

Telegram URL вычисляется при загрузке модуля, адреса проекта — при рендере карточки. Clipboard API вызывается в secure context; резервный путь — временный textarea и `execCommand('copy')` с восстановлением фокуса. Неудача показывает handle в toast. Программа не отправляет сообщения в Telegram.

Не все тексты сосредоточены в content.js: служебные заголовки, подсказки, меню и `DEVELOPER · PLAYER 01` заданы в app.js; бренд корпуса, title, description, Open Graph, canonical и noscript — в index.html. При переименовании владельца нужно проверить все три файла.

## 7. DOM, CSS и доступность

Корпус `.console` имеет ширину `min(480px,100%)`, пропорции 480/754 и `container-type:inline-size`. Геометрия и шрифты в основном используют `%` и `cqw`. Корпус стоит вертикально; поворот применён к отдельным кнопкам и динамику.

Основные зоны: верхние POWER/SOUND → рамка `.screen-bezel` и LCD → бренд → крестовина/A/B → SELECT/START → декоративный динамик и подписи. Текстуры, объём и блики созданы CSS и встроенными SVG-фильтрами. Пиксельные аватар, устройство и рисунки проектов находятся в app.js, favicon — отдельный SVG.

`frame()` формирует `.screen-top`, `.screen-main`, `.screen-footer`. Для прокручиваемой середины задан `overflow:hidden`: содержимое можно двигать программно, без нативного экранного ввода. `.lcd` имеет `pointer-events:none` и запрет выделения текста.

Контракты JS ↔ DOM/CSS:

- `#console[data-power=off|boot|on]` — подсветка и индикатор питания.
- `#power-toggle[aria-checked]`, `#sound-toggle[aria-pressed]` — переключатели.
- `.screen-content.booting/entering` — анимация загрузки и переходов.
- `.is-pressed` — визуальное нажатие корпуса.
- `.is-selected`, `aria-current`, `data-index`, `data-screen-action` — экранный выбор и его действие.
- Все `data-index` должны составлять непрерывную последовательность 0…N−1: число элементов управляет навигацией, подтверждение ищет конкретный индекс.

Адаптивные условия: при ширине >760 и высоте ≤850 px максимальная ширина корпуса 430 px; при ширине ≤480 меняются отступы, тени и некоторые детали; `pointer:coarse` расширяет области касаний; при ширине ≤350 они дополнительно увеличиваются. Минимальная ширина HTML — 320 px.

Есть `lang=ru`, скрытый h1, доступные имена кнопок, role=switch, aria-checked/pressed/busy, focus-visible и отдельный polite live region. Поддержан prefers-reduced-motion, масштабирование страницы не запрещено. Это не полноценный аудит скринридером или доказательство соответствия стандарту доступности.

Шрифты локальные: Manrope Regular/Bold и Press Start 2P под CSS-именем Pixel. Основной текст LCD использует Courier New/monospace. Лицензии обоих семейств приложены как SIL OFL 1.1. На 390 px ширина корпуса измерена как 358 px, базовый текст экрана — примерно 11.21 px; на 320 px надписи очень мелкие, что видно на скриншоте. Ширина корпуса ограничена, поэтому объём текста требует проверки в реальном LCD.

## 8. Аудио

`ButtonSounds` имеет enabled, Map пяти клипов, current и счётчик request. Аудио создаётся лениво при первом разрешённом воспроизведении, добавляется в корпус как hidden/aria-hidden, preload=auto, playsinline.

Новое нажатие останавливает предыдущий клип. При повторе использованного клипа currentTime сбрасывается только если он >0. `play()` вызывается непосредственно в обработчике пользовательского события: не добавлять перед ним await/fetch/таймер при рефакторинге. Устаревшие отказы и AbortError игнорируются. Другой отказ очищает клипы, выключает SOUND, сохраняет off и предлагает повторное включение.

Выключение SOUND, document.hidden и pagehide останавливают текущий звук. Возвращение на страницу ждёт нового нажатия. Выключение питания играет эффект off, если звук разрешён.

Генератор создаёт mono PCM WAV, 44 100 Гц, 16 bit, с короткой огибающей квадратного сигнала. Длительности: move ≈85 мс, confirm ≈190 мс, back ≈170 мс, boot ≈465 мс, off ≈155 мс. Новое имя эффекта потребует согласовать soundNames, генератор, место вызова и аудиотесты.

## 9. Запуск и публикация

Из корня проекта:

```powershell
npm start
npm run check
npm test
```

`npm install` для приложения не требуется. README указывает Node.js 18+; при изучении команды выполнены на Node.js 24.20.0 и npm 11.19.0. Проверка на других версиях Node не выполнялась.

Локальный сервер слушает `0.0.0.0:4173`, PORT позволяет выбрать другой порт. Корень вычисляется относительно serve.mjs, а не текущего каталога. `/` отдаёт index.html; MIME заданы для HTML/CSS/JS/SVG/TTF/JSON/WAV. Есть no-cache и nosniff. Пути за пределами root и скрытые пути отклоняются; HEAD возвращает заголовки без тела. Это вспомогательная раздача файлов, без API и отдельного production-процесса приложения. Через file:// ES-модули не запускаются обычным способом.

Согласно README и образцу Nginx: домен wangock.tech, релизы в `/var/www/wangock/releases/`, активная символическая ссылка `/var/www/wangock/current`, конфигурация `/etc/nginx/sites-available/wangock`. HTTP перенаправляется на HTTPS; используются файлы сертификата Let's Encrypt и certbot.timer.

Образец включает gzip, nosniff, Referrer-Policy, SAMEORIGIN, семидневное кеширование assets и запрет выдачи tests/scripts и скрытых путей. `test-results` отдельно не запрещён: в релиз следует копировать только файлы сайта и необходимые лицензии. Нет встроенного deploy-скрипта или CI. Изменение WAV/шрифта с прежним URL требует учитывать семидневный кеш; версии/хеши ресурсов в URL автоматически не добавляются.

Процесс обновления описан как загрузка нового каталога релиза, проверки, затем переключение current. Фактическое состояние DNS, TLS, systemd и содержимое production не подтверждались локальным изучением.

## 11. Как повторять браузерные проверки на Windows

При изучении создано изолированное окружение в `.tools/checks`, браузеры установлены в `.tools/browsers`. Эти каталоги уже исключены .gitignore. Python/Playwright для тестов в package.json не закреплены.

Подготовка на новом компьютере:

```powershell
python -m venv .tools/checks
.\.tools\checks\Scripts\python.exe -m pip install playwright
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Get-Location) '.tools\browsers'
.\.tools\checks\Scripts\python.exe -m playwright install chromium webkit
```

При работающем локальном сервере, из корня проекта:

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Get-Location) '.tools\browsers'
$env:PYTHONUTF8 = '1'
$env:PORTFOLIO_URL = 'http://127.0.0.1:4173'
$env:PORTFOLIO_BROWSER = 'chromium'
$env:PORTFOLIO_RESULTS = Join-Path (Get-Location) 'test-results\local-chromium'
.\.tools\checks\Scripts\python.exe tests/browser_check.py

$env:PORTFOLIO_BROWSER = 'webkit'
$env:PORTFOLIO_RESULTS = Join-Path (Get-Location) 'test-results\local-webkit'
.\.tools\checks\Scripts\python.exe tests/browser_check.py

$env:PORTFOLIO_BROWSERS = 'chromium,webkit'
$env:PORTFOLIO_RESULTS = Join-Path (Get-Location) 'test-results\local-audio'
.\.tools\checks\Scripts\python.exe tests/audio_check.py
```

Без PORTFOLIO_URL оба сценария проверяют production, что не подтверждает локальные изменения. PORTFOLIO_BROWSER выбирает один движок UI-теста; PORTFOLIO_BROWSERS — список аудиотеста. Отдельные каталоги результатов предотвращают перезапись отчётов. PYTHONUTF8 обеспечивает запись русского JSON независимо от системной кодировки Windows.

## 12. Ограничения при будущих изменениях

Три случая ниже воспроизведены через подмену content.js только в тестовом браузере. Исходный контент на диске не менялся.

1. **Длинный список и B:** при восьми проектах возврат сохраняет selected=7, но сбрасывает scrollTop с 243 к 0, оставляя выбранный элемент вне видимой области. Причина — полный рендер и отсутствие восстановления прокрутки/scrollIntoView для back.
2. **Длинное описание с sourceUrl:** в карточке становятся два пункта. Стрелки вместо пошаговой прокрутки прыгают между ссылками внизу; в эксперименте scrollTop чередовался около 358/386 px. Промежуточный текст недоступен тем же способом. При добавлении настоящих ссылок нужно проверить читаемость карточки.
3. **Пустой about:** открытие раздела вызывает `Cannot read properties of undefined (reading 'title')`. Массив должен оставаться непустым либо потребуется пустое состояние.

Также установлено чтением кода:

- Возврат восстанавливает route, но не позицию чтения длинной карточки.
- Пустые/некорректные tags, stack, features, includes и несуществующие route.index не защищены валидацией.
- Асинхронное копирование может показать toast после перехода на другой экран или выключения консоли.
- Открытие внешней вкладки показывает toast без подтверждения успеха window.open.
- Добавленные проекты, названия, handle и количество features требуют согласования с жёстко заданными ожиданиями browser_check.py.
- Новый раздел требует обновить menu и render в app.js, а при новом действии — activate/control. Нумерация и подписи экранов заданы вручную.

## 13. Где вносить типовые изменения

| Задача | Место и связанная проверка |
| --- | --- |
| Изменить тексты, услуги, цены, проекты | content.js; затем проверить вместимость LCD и ожидания UI-тестов |
| Поменять владельца/Telegram | content.js + статический бренд и метаданные index.html + служебные тексты app.js |
| Добавить демо/исходники | demoUrl/sourceUrl; допустимы абсолютные HTTP(S); проверить переключение и прокрутку |
| Добавить рисунок проекта | projectArt() в app.js и значение art в content.js |
| Новый раздел | menu/render/activate в app.js; при необходимости новый маршрут и тесты переходов |
| Изменить историю и возврат | navigation.js, затем Node-тесты и вложенные сценарии браузера |
| Изменить кнопки или клавиши | index.html + control/keyActions/keydown в app.js; проверить touch, Tab и смешанный ввод |
| Изменить корпус/адаптивность | styles.css; сохранить CSS/ARIA-контракты и проверить 320, 390, 768, 1024, 1440 px |
| Изменить звук | sound.js и/или генератор WAV; проверить пользовательское событие, повтор, выключение и возврат на страницу |
| Изменить публикацию | scripts/nginx.conf и описанный процесс релизов; учитывать кеш ресурсов и проверять удалённое состояние отдельно |

Для следующих задач исходить из этого устройства проекта. Актуализировать карту, если меняются архитектура, контентные контракты, запуск или результаты проверок.
